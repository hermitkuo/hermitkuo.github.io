本週 8 個關鍵洞察

真正重要的是每個 Skill 應負責哪一層判斷，而不是誰的 GitHub stars 最大。

01 · ROUTING

UI Skills 開始像 Design Skill Router

價值不在一次載入 130+ Skills，而在於依任務動態選擇。這代表 Skill 生態開始從 collection 走向 orchestration。

02 · MOTION

動效設計與動畫工程正式拆開

Emil Kowalski Skills 負責「要不要動、何時動、什麼節奏」，GSAP 負責「怎麼把它做出來」。

03 · PPTX

PPT Master 持續坐穩可編輯簡報核心

Native shape、connector、chart、table、slide master 讓它更接近真正 PowerPoint production，而非 HTML 截圖包裝。

04 · QA

Impeccable 已成 Design QA Harness

不應只視為美化 Skill。它更適合處理 critique、audit、harden、responsive、a11y 與 edge case。

05 · WEB DECK

Frontend Slides 的角色反而更清楚

它不是最佳 PowerPoint，而是最乾淨的 Web-native presentation 路徑，適合技術架構、研究故事與可直接分享的 HTML deck。

06 · BOUNDARY

Taste Skill 應限定場景

最適合 landing、portfolio、editorial redesign；不應主導高資訊密度 Dashboard、patient list 或多步驟臨床操作介面。

07 · LINTING

Hallmark 正從 taste rules 走向 mechanical QA

值得追的是 checker / CI，而不是更多 theme。長期趨勢是 design taste → rule → machine-testable rule。

08 · HUMAN LOOP

Dashi 的價值是「AI 做完，人類接得回來」

Browser edit → AI revise → editable PPTX 是重要方向。對真實簡報流程而言，人類 round-trip 往往比一次生成的美感更重要。

推薦生產 Stack

不要建立「一個超級設計 Agent」，而應讓各 Skill 各自負責清楚的責任邊界。

Web / Dashboard

UI Skills Router→Frontend Design / UIUX Query→Implementation→Impeccable QA

Motion

Emil Opportunities→Emil Animate→GSAP→Review Animations

Web Presentation

Frontend Slides→Impeccable→Browser QA

Formal PPTX

PPT Master→Render QA→PowerPoint Human Finish

Human + AI Editing

Dashi→Browser Edit→AI Revise→Editable PPTX

Brand / Editorial

Taste or Hallmark→Implementation→Impeccable

Not-to-do

最容易浪費時間的不是少裝一個 Skill，而是責任重疊與 context 污染。

不要一次載入 100+ UI Skills

Router 的價值就是按需載入。全量常駐只會增加 context、規則衝突與不可預測性。

不要讓四套設計哲學同時主導

UI/UX Pro Max、Taste、Hallmark、Impeccable 應分別扮演資料庫、視覺方向、anti-slop build 與 QA，而不是同時發號施令。

不要把 HTML PPT Studio 當唯一長期主線

它功能完整，但目前在 Web 自由度、可編輯 PPTX、人機 round-trip 等面向都有更明確的替代方案。

不要把社群熱度當導入理由

真正的導入 gate 應是：可安裝性、維護狀態、輸出品質、工作流價值、授權與 repository provenance。

本週如果只新增兩個： UI Skills 與 Emil Kowalski Skills。前者解決「該叫誰做」，後者解決「什麼情況不該做動效」。這代表 Design Skills 正從 prompt collection 走向真正的 orchestration 與 harness。
