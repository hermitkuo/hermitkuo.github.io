本月一句話

August 的核心不是「AI 又更會畫 UI」，而是 UX 的稀缺資源已從產製能力轉為判斷、驗證與治理能力。

Production is cheap; judgment is scarce. 當 AI 可以在幾分鐘內生成 prototype、功能與完整 workflow，UX 的價值會往 evaluation infrastructure × evidence quality × delegation design 移動。

本月 6 個高訊號變化

排序依據：結構性影響 × 可立即落地 × 是否跨越單一工具。

01 · Highest Signal

UX 進入「Custodial Era」：產製比評估快

NN/g 8/28 明確指出 AI 讓 prototype 與 feature 生成速度超過 UX 能評估的速度，因此團隊更常面臨「先做出來，再清理 UX debt」。真正瓶頸從畫面產製轉成：這東西該不該存在、是否可理解、可靠、可信。

行動：把 UX review 前移成 release gate；至少檢查價值、task success、failure state、evidence 與 trust。
02 · Highest Signal

AI UX evaluation 必須從單次 demo 升級為分布評估

NN/g 8/14 強調：一次成功輸出只是 example，不是 evaluation。AI 的 input variance 與 run-to-run variance 都必須被測量，否則漂亮 demo 會系統性高估產品可靠度。

行動：建立 representative cases × repeated runs × rubric × confidence interval 的 AI UX eval harness。
03 · High Signal

Research evidence 與 AI-generated plausibility 正式分家

NN/g 8/28 對 empathy mapping 的界線很清楚：AI 可以整理真實研究資料，但不能把生成的「像使用者會說的話」當成研究證據。Dogfooding 也不能代替真實使用者。

行動：每一個 insight 都保留 evidence provenance：real observation / interview / log / support ticket / AI hypothesis。
04 · High Signal

Agentic UX 的核心從聊天介面轉成「授權設計」

8/26 OpenAI 公布的 agent 失控事件再次提醒：當 agent 能跨工具、網路與系統行動，UX 不只是對話設計，而是 scope、permission、checkpoint、monitoring、override 與 recovery。模型越強，這層越重要。

行動：把 autonomy level 設為產品屬性，不讓模型能力自動等同於執行權限。
05 · Emerging Signal

Design system 正變成 Agent-readable Operating System

Figma MCP 的方向已從讀取畫布走向讓 agent 讀取 components、variables、layout 與 design context，甚至回寫原生設計。設計系統的價值從「維持一致」擴展為「提供 agent 可執行的約束」。

行動：把 component rules、tokens、content rules、accessibility、review heuristics 做成 machine-readable context，而非只留在 PDF/wiki。
06 · Research Signal

AI 正從模仿成品，轉向學習人類設計「軌跡」

8/20 的 FigmaTrace 蒐集 200+ 小時專家設計操作，轉成 3,469 條 design trajectories；訊號在於：高品質設計 AI 的下一步不是更多 screenshot，而是學習 phase、decision、revision 與 taste 的過程資料。

行動：開始保留設計決策歷程、review rationale 與修正原因，未來它們會比最後的 mockup 更有訓練與治理價值。

本月建議：把 UX workflow 改成 Eval-first

不要讓 AI 產出直接進 production。推薦的最小 agentic UX pipeline：

1 · Intent明確任務與成功條件
2 · Contextrole / state / policy / evidence
3 · Generateagent 產生方案或動作
4 · Evaluaterubric + edge cases + repeat
5 · Authorize依風險決定 approve / auto
6 · Observemonitor / audit / recover

未來 30 天最值得學的 5 件事

不是工具清單，而是會持續升值的能力層。

01 · AI Eval Design代表性案例、重複測試、rubric、failure taxonomy、confidence。
02 · Delegation UXSuggest / Draft / Confirm / Act / Monitor / Undo。
03 · Context Engineering把 research、policy、design rules 組成 agent 可讀 context。
04 · Evidence Provenance讓每個 UX insight 可追溯到真實資料，而非 plausible output。
05 · Design Trajectories保存 decision → iteration → critique → correction，而非只存終稿。

Not-to-do

這些方向目前噪音高、長期護城河低，或容易製造 UX debt。

不要投入太多

  • 「再加一個 AI chat sidebar」：沒有 workflow integration 的聊天入口通常只是 feature theater。
  • One-shot demo 驗收：AI stochasticity 讓單次成功沒有可靠度意義。
  • Synthetic persona 當 research：可用來產生 hypothesis，不可冒充 evidence。
  • Prompt 技巧競賽：長期價值正在移向 context、skills、evals 與 data provenance。
  • 過度擬人化 agent：可信度應來自 transparency、bounded authority 與可逆性，不是 personality。

值得把時間移過來

  • 建立 reusable UX eval cases。
  • 畫 failure / recovery flow，不只 happy path。
  • 將 design system 規則 machine-readable。
  • 把 human approval 放在真正高風險節點。
  • 建立 production telemetry：override、correction burden、recovery success、time-to-confidence。

下月追蹤問題

如果沒有形成可驗證的變化，就不升級為「趨勢」。

Watch 01

AI eval 是否進入 DesignOps 標配？

觀察 designers 是否開始直接維護 test cases / rubrics / acceptance thresholds，而不是完全交給 engineering。

Watch 02

Design system 是否開始原生支援 agents？

追蹤 tokens、components、rules、content、a11y 與 skills 是否形成統一 machine-readable layer。

Watch 03

Autonomy patterns 是否收斂？

觀察 permission ladder、preview-before-action、undo、audit trail、escalation 是否跨產品形成穩定模式。

Radar verdict
2026 年 UX 學習的護城河，不是更快生出介面，而是能把 人類需求 → machine-readable context → agent action → measurable evaluation → safe recovery 串成一條可治理的產品系統。
